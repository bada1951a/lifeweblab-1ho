## 1. 미수금과 결제 실패 상태 확인

해외 고객의 청구서가 미납 상태이고 카드 시도에 `generic_decline`이 표시된 상황을 가정하겠습니다. 실제 수행한 사례나 검증된 통계가 아닌 점검 예시입니다. 모호한 결제 기한, 카드 거절, 송금 지연과 분쟁은 각각 다른 처리 상태입니다.

계약상 지급기한, 인보이스 상태, 결제 시도 ID와 실제 입금 내역을 한 표에 연결하세요. 청구서가 미납이라는 사실만으로 자금이 플랫폼에 묶였다고 판단할 수 없습니다.

![Troubleshooting Guide](/images/billing-photo/billing-32.jpg)

## 2. 원인을 구분하는 기준

<strong>카드 거절:</strong> `generic_decline`은 상세 원인이 불명확하거나 Stripe 측 차단이 관련된 경우에 표시될 수 있습니다. 실제 결제 상세에서 카드사 거절·차단·API 오류를 구분합니다.

<strong>인보이스 검토:</strong> 품목, 계약 금액, 지급기한과 청구 정보를 원본 계약과 대조합니다. 특정 세무 문구나 양식을 모든 거래에 일괄 추가하면 해결된다고 단정할 수 없습니다.

<strong>은행 송금:</strong> 별도 송금이 있었다면 은행의 참조번호로 추적을 요청합니다. 카드 결제 시도의 오류 코드로 은행 송금 상태를 설명하지 않습니다.

## 3. 단계별 조치

1. 결제 상세에서 필요한 인증과 오류 정보를 확인합니다. 고객에게는 지원되는 안전한 인증·결제 화면을 안내합니다.
2. `automatic_payment_methods[enabled]=true`는 결제 수단 자동 선택 설정이며 3DS 강제 인증 설정이 아닙니다. 인증 흐름의 구현 변경은 공식 문서를 기준으로 별도 검증해야 합니다.
3. 지급기한은 계약에 따라 날짜와 시간대를 명확히 하되, 기존 계약을 일방적으로 바꾸지 않습니다. 연체 이자나 서비스 중단 조건은 적용 법률과 계약을 확인합니다.
4. 인보이스 정정 이력을 보존하고, 대체 결제 경로를 이용할 때는 국가·통화·계정별 지원 여부와 비용을 확인합니다.

## 4. 분쟁과 기록 관리

분쟁이 발생하면 해당 거래의 Dashboard에 표시된 제출 기한과 요구 증빙을 확인합니다. 모든 사건에 48시간이라는 동일한 마감이 적용되거나 기한 내 제출만으로 승소·수수료 면제가 보장되는 것은 아닙니다.

계약, 납품 기록과 고객 연락 내역을 사실대로 보존합니다. 인보이스 미수금의 원인 비율이나 승인 속도 개선 수치를 근거 없이 제시하지 않습니다. 결제 담당자와 문서 정정을 합의하고 처리 상태를 공유하는 것이 점검의 출발점입니다.

## 5. 자주 묻는 질문 (FAQ)

<strong>질문:</strong> 은행 송금 대신 다른 서비스를 쓰면 항상 빠르고 저렴한가요?

<strong>답변:</strong> 국가·통화·지원 자격·환율과 수수료에 따라 다릅니다. 제공업체의 실제 조건을 비교하고 기존 거래 상태도 확인하세요.

<strong>질문:</strong> 미수금이 생기면 바로 서비스를 중단해도 되나요?

<strong>답변:</strong> 계약상 통지·유예 절차와 적용 규정을 확인해야 합니다. 일괄적으로 7일 뒤 중단하는 규칙이 모든 거래에 안전한 것은 아닙니다.

<strong>질문:</strong> Stripe 분쟁은 언제까지 대응해야 하나요?

<strong>답변:</strong> 해당 분쟁 화면의 제출 기한을 기준으로 준비하고 요구된 자료를 제출하세요. 검토 결과와 수수료는 사건별로 다릅니다.

참고: [Stripe 3DS 인증](https://docs.stripe.com/payments/3d-secure/authentication-flow), [분쟁 대응](https://docs.stripe.com/disputes/responding).
