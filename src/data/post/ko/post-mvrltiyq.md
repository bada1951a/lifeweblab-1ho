## 1. 구독 결제 실패를 분류하기

정기 결제일에 여러 고객의 결제가 실패한 상황을 가정해 보겠습니다. 이는 실제 운영 성과나 실험 결과가 아닌 점검 예시입니다. 실패가 늘었다는 사실만으로 카드 만료가 유일한 원인이라고 단정하지 말고, 코드와 결제 수단 상태를 먼저 나눠 봅니다.

<strong>고객·구독·인보이스·결제 시도 ID</strong>를 연결해 이미 성공한 거래와 미납 거래를 구분하세요. 자동 재시도와 수동 청구를 함께 운영한다면 중복 처리 여부도 확인합니다.

## 2. 만료·추가 인증·일시적 거절 구분

만료된 카드에는 고객의 카드 정보 갱신이 필요할 수 있습니다. 모든 거절이 시간이 지나면 해결되는 것은 아니며, 소프트 거절을 방치하면 자동으로 하드 거절로 바뀐다고 설명할 수도 없습니다. 코드 표기와 분류는 결제 제공업체의 실제 응답을 기준으로 합니다.

추가 인증이 필요한 거래는 고객이 참여하는 인증 화면으로 안내합니다. 세무 양식이나 중계은행 문제를 카드 거절의 일반 원인으로 묶지 마세요.

## 3. 재시도 설정 점검 순서

1. <strong>실패 목록 정리:</strong> 인보이스 상태와 최근 시도 결과를 확인하고, 결제 수단 갱신·고객 인증·지원 문의가 필요한 건을 나눕니다.
2. <strong>재시도 정책 확인:</strong> Stripe Billing의 Revenue recovery에서 설정을 점검합니다. Smart Retries와 사용자 지정 일정은 구분되며, 1·3·5일 간격이 모든 계정의 최적값인 것은 아닙니다.
3. <strong>갱신 위치 확인:</strong> 구독에 기본 결제 수단이 지정돼 있다면 고객 기본값만 바꿔도 해당 구독이 새 수단을 사용하는지 확인해야 합니다.
4. <strong>알림과 중복 방지:</strong> 고객에게 안전한 카드 갱신·인증 경로를 안내하고 자동 처리 상태를 기록합니다. 이유 없는 반복 청구는 피합니다.

## 4. 운영 체크리스트

실패 코드, 고객 안내 시각, 갱신 여부, 다음 조치와 실제 성공 여부를 남기세요. Stripe는 결제 수단 부재나 특정 하드 거절 등에서는 자동 재시도를 하지 않습니다. 재시도 횟수만 보고 실제 청구가 실행됐다고 판단하지 말고 결과 상태를 확인합니다.

서비스 유예·중단 정책은 계약과 고객 고지에 맞게 정합니다. 만료 전 안내는 도움이 될 수 있지만, 모든 실패나 해지를 막는다고 보장할 수는 없습니다. 인보이스 법정 필수 항목은 거래 국가와 세금 적용에 따라 확인합니다.

## 5. 자주 묻는 질문 (FAQ)

<strong>질문:</strong> 스마트 재시도를 켰는데 왜 계속 실패하나요?

<strong>답변:</strong> 재시도 대상인지, 결제 수단이 있는지, 고객 인증이나 갱신이 필요한지 확인하세요. 재시도 설정만으로 모든 거절이 해결되지는 않습니다.

<strong>질문:</strong> 고객 기본 카드를 바꾸면 모든 구독에도 적용되나요?

<strong>답변:</strong> 구독에 별도 기본 결제 수단이 있으면 그 설정이 우선할 수 있습니다. 실패한 결제에서 실제 사용한 필드와 갱신 위치를 확인하세요.

<strong>질문:</strong> 수수료를 줄이려면 무조건 재시도를 줄이면 되나요?

<strong>답변:</strong> 비용과 회수 결과를 함께 확인해야 합니다. 제공업체·계약별 조건과 재시도 가능 여부를 검토하고 고객 인증·갱신이 필요한 건은 별도 처리하세요.

참고: [Stripe 자동 재시도](https://docs.stripe.com/billing/revenue-recovery/smart-retries).
